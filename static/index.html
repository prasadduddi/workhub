🔑 Change a password everywhere

  
When a user's password changes, set the new one on every connection that logs in as that user. The old password is kept in each connection's history.

👤 Your profile

  
Your own details, kept only on this PC (shared by all your workspaces). Your email is where a PIN reset code is sent, and it's used as your Jira login when that is empty.

📝 Session logs

  
  
What each SSH terminal shows — your commands and their output — is kept per server and day in your data folder, as plain text (typed passwords aren't shown by servers, so they aren't saved). Logs older than 180 days are removed.

↗ Program locations

  
Used by “Open in PuTTY / FileZilla / DBeaver / SQL Developer”. Leave a box empty to let WorkHub find the program (a running copy, usual install folders, or an unzipped copy in your user folder, Downloads, Desktop or C:\Tools).

  

  



  
🛟 Backups

  
Made automatically when WorkHub starts and every morning — only when something changed. The newest 30 are kept, in a folder next to your data folder (so they survive if the data folder is lost):

  

  

  

    Also copy backups to — e.g. OneDrive, so they are safe if this laptop is lost or replaced
    

    

    

  

  
To restore: quit WorkHub, unzip a backup into an empty folder, start WorkHub and pick that folder with Data location…. With a 🔐 master password on, a backup opens on any PC with that password (e.g. a new laptop, from OneDrive); without one it opens only for your Windows login on this PC.

Naming rules — 

    
When a server's or link's host name contains the text on the left, it is named with the label on the right
      (e.g. pay-bat-01 → Batch – pay-bat-01). One rule per line. Only this workspace; names you typed yourself are kept and get the label as a tag.

    
    

  




  

    
Jira settings (this workspace)

    
    
    
    
    

      

      
A Jira window opens: log in as you normally do (SSO / MFA). WorkHub notices when you're in and hides the window — closing it is fine too. Tick “Remember me” / “Stay signed in” if the login page offers it. WorkHub keeps the session alive while it runs and signs in again by itself when it can.

    

    
    
Jira Cloud: create an API token at id.atlassian.com → Security → API tokens. Jira Server/DC: your profile → Personal Access Tokens. The token is stored encrypted and never shown again.

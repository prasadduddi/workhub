# WorkHub

Portable work toolkit for Windows: collects hosts, ports, URLs and logins from the
clipboard, plus PuTTY-style SSH and command prompts, FileZilla-style SFTP/FTP,
Oracle/PostgreSQL SQL window, Git browser, bookmarks and a Notepad++-style editor.
One file, no install, no admin rights, no Python, Java or Oracle client needed.

## Two versions (same app, same data)
| File | What it is |
|---|---|
| `WorkHub-web.exe` | **Web version** – opens in your browser; a small console window shows it's running. |
| `WorkHub-Desktop.exe` | **Desktop version** – its own window (Microsoft Edge WebView2, built into Windows 10/11), no console. Closing the window stops it. Links open in your normal browser. If WebView2 is missing it falls back to the browser. |

Both use the same data, so you can switch between them. Run one at a time per workspace
(starting the other just opens a window onto the one already running).

## Get it onto a Windows laptop

**Easiest (no Git or Go needed):** open this repository's **Releases** page in the
browser, download `WorkHub-Desktop.exe` and/or `WorkHub-web.exe` (or the zip with both), save it
in a folder you own such as `Documents\WorkHub`, and double-click it.

**Build it yourself on the laptop (no admin needed):**
1. Download the Go *zip* for Windows from https://go.dev/dl/ and extract it to e.g. `%USERPROFILE%\go-sdk`.
2. Get the code: `git clone <this repo>`, or use GitHub's **Code → Download ZIP**.
3. In the project folder: `%USERPROFILE%\go-sdk\go\bin\go build -o WorkHub-web.exe .` (web) and
   `%USERPROFILE%\go-sdk\go\bin\go build -tags desktop -ldflags "-H windowsgui" -o WorkHub-Desktop.exe .` (desktop)
   (this downloads libraries from the internet; a company proxy may need `set HTTPS_PROXY=...`).

When it starts, your browser opens WorkHub. Keep the small console window open;
closing it stops WorkHub. "Windows protected your PC" → **More info → Run anyway**.

## Your data
- Stored in `%LOCALAPPDATA%\WorkHub\data`, encrypted and tied to your Windows login.
  Every version of the exe, run from any folder, uses the same data, so updating = run the new exe.
- Nothing is stored in this repository. Data from one laptop cannot be opened on another.
- First run imports old `workhub-data` folders it finds; **Import data…** and **Data location…**
  in the sidebar handle other cases. If data can't be opened, a recovery page lets you pick another folder.

## Passwords that protect WorkHub
- **Master password** (☰ → 🔐 Master password…): when it is on, WorkHub asks for it every time it
  starts, and the key to your data is sealed with it, so a copied data folder can't be opened
  without it. You get a one-time recovery code when you set it; typing that code instead of the
  password lets you choose a new one. Each person sets their own.
- **PIN** (☰ → 🔒 Lock): locks the open app after some idle minutes.
- **Team access password** (optional, per build): a copy of WorkHub asks for it once per PC before
  it can be used. Set it with `go run ./tools/accesshash` (writes only a salted hash to `access.go`;
  `-off` removes it), then build or tag a release. The code is public, so this keeps casual users
  out of a downloaded copy, not someone who builds their own.

## Separate workspaces (one per client)
Each laptop keeps its own data. For a second client on the same laptop, make a shortcut to
`WorkHub-web.exe -workspace ClientB`: it gets its own data, key, port and session.

## Releasing a new version
Push to `main` and GitHub Actions builds and tests it (the exe is under the run's *Artifacts*).
Tag it to publish a release:

    git tag v1.1 && git push origin v1.1

## Developing
    ./build.sh                 # dist/WorkHub-web.exe + dist/WorkHub-Desktop.exe, dist/workhub-local, dist/WorkHub-<timestamp>.zip
    go test -short ./...       # quick tests; without -short also runs a real PostgreSQL test

Options: `WorkHub-web.exe -workspace NAME -data D:\folder -port 47821 -no-browser`

The app icon (taskbar, Task Manager, Explorer, browser tab) is generated by
`go run ./tools/genicon`, which writes `rsrc_windows_amd64.syso` (linked into both
Windows builds automatically) and `static/icon.png`.

## Try it with demo data

`tools/demolab/run-demo.sh` (Mac/Linux, needs Go and Python 3) starts WorkHub with made-up data for a
fictional customer — browser bookmarks, servers, databases, a tunnel, FTP, groups, naming rules, folders, a Git
repo and Jira issues — plus two pretend SSH/SFTP servers (127.0.0.1:2222 and :2223) and a pretend Jira.
`run-demo.sh stop` stops it; `run-demo.sh reset` deletes the demo data. Nothing touches your real workspace.
